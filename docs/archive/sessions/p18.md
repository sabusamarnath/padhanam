- Reflection 1 — Did correlation hold across three sources, or did the no-shared-identifier inference need a confidence floor? Both, and the floor earned itself. The inference holds: facets sharing a normalised title correlate, a corroborating time anchor confirms, a title-only match is a candidate — and the floor (0.8) is exactly what separates "auto-link the task to the meeting that share a title and a day" from "surface, for the operator to confirm, the task and the meeting that share a title but sit 40 days apart." The decisive lesson was a **live-data-distribution** one (captures [S66], the sixth live-substrate instance and a new face): the first matcher grouped purely by title and collapsed ~84 recurring calendar instances of one title into a single 84-facet mega-unit — internally correct, fully unit-tested on synthetic fixtures, and wrong on the real corpus. The fix is the genuinely-correct model D166 implies: **a unit binds at most one facet per type** (the cross-tool link is the differentiator, not same-type recurrence collapse), with same-type duplicates staying separate units and cross-type facets pairing one-to-one by nearest time. Without the live run this would have shipped green.

- Reflection 2 — What does P19 need from the unit that is not there yet? P19 reads orphan work (a unit pointing at no goal) and the neglected goal (a goal nothing points at), against the seeded goals. From this layer it has what it needs: a stable `:Unit` node (deterministic id, survives re-correlation) to attach a goal-facet edge to (the P19 `LEVER_FOR`-style edge from `:Unit` to `:Outcome`), and `list_units` to enumerate units for the orphan scan. Two things P19 must handle that S66 surfaced: (a) **recurrence noise** — 979 single-facet units, most of them recurring calendar instances, would each read as an "orphan" without dedup; P19's orphan read should fold recurrences (by `recurring_event_id` or title) so the neglected-goal/orphan-work signal is not drowned (the reverse-Kano restraint lesson, [S57], applied to a read rather than a push). (b) **the homeostatic/owed clause** (D166): a meeting that is pure maintenance is not "orphan work," so the orphan read must not flag every goal-less unit — the purpose-is-broader-than-goal-advancement clause is P19's to honour.

- Reflection 3 — Did the daily_driver-owns-units placement hold, or should this have been a new context? It held, and it was the right reconcile-and-proceed call. The goal-layer precedent (S62: graph capability in ingestion's wrapper, the concept owned by daily_driver, bridges in apps) transferred exactly — correlation added one domain module, two consumer ports, two use cases, two apps bridges, and a route, with no new context boundary and no new import-linter contract. The one hexagonal catch the linter found (the view projection in domain importing the read record from ports) was the right kind of catch: it forced the read records (`UnitRecord`/`UnitFacetRef`) into the domain where the GoalGraphPort-returns-domain precedent already puts them, leaving ports importing domain (legal) rather than the reverse. A separate `contexts/work_units/` would have been a new context boundary for a layer that is, structurally, a second instance of the goal-layer shape — over-engineering against the established sibling.

methodology: the live run was load-bearing in a new way — it caught a *pure-domain* bug (the matcher), not a substrate or vendor-contract bug, because the failure lived in the gap between the author's assumed data distribution (synthetic fixtures: distinct titles, one-of-each-type) and the real corpus (many same-title recurrences). The standing "verify on live substrate" discipline already covered substrate behaviour, vendor contracts, runtime state-churn, the browser boundary, and mock-blindness; this adds *real-data-distribution* as a sixth face, recorded as a new clause on the held live-substrate-verification-gate candidate. The corrective generalises: a heuristic over ingested data is not done when its unit tests are green; it is done when it has run against a representative real corpus.
