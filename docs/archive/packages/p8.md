## Goal

Agent runtime substrate. P8 ships the platform's ability to invoke
authored agents end-to-end against the methodology v3 shape from D86:
roles are first-class primary aggregates; methodologies are playbooks
composing roles via `role_refs` plus workflow specification plus per-
role overrides; skills defer to Phase 2 per D86 sub-commitment (d).
By P8 close, the agent runtime invokes one agent end-to-end with full
instrumentation (SSE-streamed eleven-event vocabulary per D90, nested
OTel span hierarchy with cost roll-up extending D49 and D57, two-row
audit per invocation per D26, platform invariant enforcement at the
tool-invocation boundary per D82 with classification-to-invariant
mapping per D89). Two end-to-end demonstrations exercise the substrate
in product form at narrow and broad artifact scales through the same
runtime; the `padhanam agent run` CLI consumes the SSE endpoint as the
first product-form transport consumer.

## What carries into the P8→P9 boundary

- **Retrieval-aware role allowlists.** Phase 1 demos showed the
  substrate working end-to-end but without retrieval grounding
  because all migration-seeded roles ship with empty tool_allowlists.
  Per-invocation allowlist override OR role-allowlist tightening
  (adding the retrieval tool reference to the relevant roles) at
  Phase 2 makes source-grounded artifacts the default. Activates
  at the first authoring evidence demanding it.

- **Per-invocation retrieval-constraint threading at ToolInvoker.**
  The Phase 1 `ToolInvokerAdapter` constructor accepts retrieval
  constants (top_k, min_score, retrieval_strategy, filter_tree)
  at composition time; per-role retrieval constraints from the
  effective bundle do not thread through to the tool invoker on
  each invocation. Phase 2 substrate refinement queued at
  `apps/api/_agent_runtime_wiring.py` module docstring.

- **Cross-app adapter location cleanup.** S30b's production wiring
  imports adapter classes (`RoleLookupAdapter`,
  `MethodologyOverridesLookupAdapter`, `ToolDefinitionsLookupAdapter`,
  `ToolInvokerAdapter`, `AgentRetrievalClientAdapter`) from
  `apps/cli/_cross_context.py` because both `apps/cli/` and
  `apps/api/` need them and the adapters have no CLI-specific
  dependencies. Phase 2 cleanup relocates to a shared `apps/`-level
  module; Phase 1 cross-app import is the pragmatic call.
