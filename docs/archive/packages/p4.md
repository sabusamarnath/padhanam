Closed at S15 close. Reconciles against the v1 epic note at
[charter/packages/p4-epic.md](../../../charter/packages/p4-epic.md) per D43.

## Goal

End-to-end cost dimension wired through the inference path. Per-tenant
cost-attribution column on the control-plane registry. Cost-ceiling
configuration columns landed alongside as forward-affordance for
Phase 2 enforcement. Inference path resolves a tenant context object
from the registry at request time, propagating jurisdiction and
cost-attribution identifier through to the LiteLLMAdapter span. Two
sessions; closes when tenant A and tenant B both produce traces in
Langfuse with `gen_ai.cost.*` and `tenant.*` attributes correctly
populated, with no cross-tenant leakage.

## Drift surfaced

- **The S14 migration commit's scope expanded mid-build.** The Alembic revision adds a NOT NULL column; the registry adapter's insert path needed updating in the same commit because the adapter is broken otherwise. Surfaced as a methodology observation in the S14 session log entry and inherited as a session-prompt convention going forward: schema-tightening migrations (NOT NULL adds, CHECK additions, FK enforcements) should explicitly list adapter consumers in the substantive-work shape.
- **The S15 framing committed `classification` as a TenantContext field, but no schema column existed.** Surfaced during pre-write reconciliation when the framing conversation cross-referenced `charter/schema.md`. Resolution: classification deferred per option C from framing, captured in D50 with the schema-verification surfacing as the cause. Lesson promoted: field commitments at framing should be verified against `charter/schema.md` before close, because schema state is the truth and v1 epic notes that contradict it are paper.
- **The S14 commit-shape granularity question recurred at S15 commit 2/3 split.** S15 prompt named commit 2 as the resolver and commit 3 as the propagation+attributes. The naïve order (port signature widening in commit 2) produces an intermediate broken state where the resolver returns a TenantContext that has nowhere to flow. Resolution: commit 2 keeps the port signature accepting `tenant_id`, the router's resolver extracts `tenant_context.tenant_id` for the call, then commit 3 widens the port and switches the OTel namespace together. The split preserves the prompt's commit shape without producing a broken intermediate state, but the discipline is fragile — same shape as the S14 lesson.
- **The forward-affordance comments on the cost-ceiling columns held against AST tests, but no enforcement prevents accidental future consumption.** Surfaced in S14 reflection. The structural-promotion threshold (third instance) would trigger an AST test that walks `contexts/` and `apps/` for any reference to `cost_ceiling_usd_monthly` or `cost_ceiling_action` outside the registry adapter's `Table` definition and the migration file. Not promoted at P4 close because the rule has not bitten yet; recorded as a forward note.
- **The pricing-table format will need a structural change at the moment Phase 2 introduces multi-region or rate-card complexity.** Surfaced in S14 reflection. The format-(b) decision (Pydantic + dict) is honest at the current single-region, two-row scale; the YAML/TOML escape hatch (format c) is the cleanest landing once that complexity arrives.

## Durable lessons

- **Schema-and-consumer pairs travel together at the commit boundary.** A migration that tightens a constraint (NOT NULL, CHECK, FK) cannot land cleanly without the adapter consumer update because the migration is broken state on its own. Either the prompt's substantive-work shape lists the adapter consumer explicitly, or the commit-shape granularity treats the schema-and-consumer pair as one commit. Surfaced at S14 and reinforced at S15 commit 2/3 split.
- **Field commitments at framing should be verified against `charter/schema.md` before close.** S15 framing committed `classification` as a TenantContext field with no schema column. The reconciliation cost was small (option C deferral) but the framing convention is the prevention.
- **Padhanam-domain OTel namespace is the correct posture while standards stabilise.** D27's portability boundary commitment plus D37's `tenant.*` precedent plus D49's `gen_ai.cost.*` precedent plus D50's `tenant.cost_attribution_id` extension form a consistent pattern: the attribute names live in the Padhanam domain, the OTel SDK carries them through, and the rename cost is local to the adapter span if a working draft converges. Same forward-compat shape across four D-entries; the pattern earns the name.
- **Hybrid Depends + parameter propagation is the right pattern when the resolution involves I/O at a request boundary.** Pure-Depends propagation through internal layers couples the use case to FastAPI; ContextVar inverts the explicit-passing pattern that the inference path follows from S7. Keeping Depends at the router boundary for the I/O step (registry lookup) and reverting to explicit parameters thereafter preserves both seams.
- **The structural-promotion threshold did not trigger in P4** because no comment-level rule bit three times. P4 is also short enough (two sessions) that the threshold is hard to hit. The convention from P3 holds; it does not prescribe new structural tests when the recurrence is absent.

## What this package leaves to P5 and beyond

- **Classification field on TenantContext.** Lands at the package that genuinely consumes it (P7 or P8 per the epic note's out-of-scope section). The TenantContext value object is the right structural home; adding the field there in a later session is a one-line edit plus a registry-row column.
- **Tenant-configuration tables.** Premature scope while no consumer reads them. Land when classification gating, retention policy, or other tenant-configuration consumers arrive.
- **Cost-ceiling enforcement.** Configuration columns landed at S14 alongside the cost-attribution column per the same retrofit-avoidance logic. Reading and enforcing the columns defers to Phase 2 per `charter/deferred-decisions.md`. The CHECK constraint on `cost_ceiling_action` keeps the action space pinned at the schema layer until Phase 2 enforcement architecture activates.
- **Cost-per-successful-task evaluation metric.** P5 territory per D8 and D41.
- **Cost-aware optimization recommendations.** P11 territory; the cost dimension at the trace level is now ready for the recommendation engine to consume.
- **Multi-tier model routing, progressive throttling.** Phase 2 territory per `charter/deferred-decisions.md`. Single-model dev environment makes these premature.
- **Jurisdiction-aware inference routing.** Single-region in dev; the `tenant.jurisdiction` attribute is now on every adapter span, so the routing abstraction has data to read against when production deployment context arrives.
- **Pricing-table shape evolution to YAML/TOML under `ops/`.** Lands when multi-region or rate-card complexity justifies the file-IO load surface.

## Delta against the v1 epic note (per D43)

The v1 epic note at `charter/packages/p4-epic.md` was written at P4 open with classification as a fourth TenantContext field, three `gen_ai.cost.*` attributes, and a strict two-D-entry forecast. Reality at P4 close diverges in four named ways:

1. **`classification` field deferred from TenantContext.** The v1 epic note named four fields on TenantContext: tenant_id, jurisdiction, classification, cost_attribution_id. S15 framing surfaced (via cross-reference against `charter/schema.md`) that no `classification` column exists on `tenant_registry` and no tenant-configuration table exists either. Per framing decision option C, classification is deferred from TenantContext for P4 entirely. TenantContext carries three fields, not four. Classification lands at the package that genuinely consumes it (P7 or P8 per the v1 out-of-scope). The v1 epic note's acceptance criterion #6 ("the tenant context object carries `tenant_id`, `jurisdiction`, `classification`, and `cost_attribution_id`") is reconciled here: at close, the carried fields are tenant_id, jurisdiction, cost_attribution_id — three not four. The lesson promoted: field commitments at framing should be verified against `charter/schema.md` before close.

2. **Four `gen_ai.cost.*` attributes rather than three.** The v1 epic note's S14 framing named three (`input_usd`, `output_usd`, `total_usd`). The S14 build surfaced the need for a fourth, `gen_ai.cost.pricing_status`, as the drift signal for unknown-model lookups (`table_hit` for known models, `unknown_model` for routing-table-vs-pricing-table mismatches). The fourth attribute lands without breaking the v1 commitment; it is the additional structural shape the build surfaced.

3. **Two D-entries shipped, matching the forecast.** D49 (cost-capture wiring shape, S14) and D50 (TenantContext shape and propagation, S15). The v1 epic note flagged additional D-entries as possible if structural decisions surfaced; none did beyond the two forecast.

4. **No new import-linter contracts; no new AST tests.** The v1 epic note's acceptance criterion #8 implicitly assumed contract count would hold at 15 (the P3-close number). At P4 close, count is 15 unchanged. The structural-promotion threshold did not trigger in P4 because no comment-level rule bit three times. No drift here; the criterion holds.

The reconciliation cost is captured in this delta paragraph; the v1 epic note is preserved unedited per D43's literal wording.
