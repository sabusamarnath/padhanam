```
- **D88: Agent runtime architecture — AgentExecutor port, AgentLoopExecutor adapter, D87 resolver at agent context, retrieval-as-only-callable at Phase 1** (Package P8, Session S27b)
  - Choice. The agent runtime ships as a port-plus-adapter at `contexts/agent/`. `AgentExecutor` port at `contexts/agent/ports/executor.py` declares `execute(agent_context: AgentInvocationContext) -> AgentResult`. `AgentLoopExecutor` adapter at `contexts/agent/adapters/outbound/agent_loop_executor.py` implements LLM-with-tool-loop against LiteLLM per D4. The loop's tool surface at Phase 1 is retrieval-as-only-callable: the loop knows about retrieval as a hardcoded internal callable; the RetrievalClient port from D60 and D66 is invoked when the LLM requests retrieval. Other tool names at Phase 1 return errors. S28b's tool registry replaces this hardcoded surface with registry lookup plus classification enforcement plus invariant checks per D82.
  - D87 resolver placement. The composition of role base plus methodology per-role overrides happens at `contexts/agent/application/composition.py`, not in the methodology context. Composition algorithm: for soft fields with augment mode, concatenate role base + "\n\n" + methodology override value; for soft fields with replace mode, substitute the methodology override value; for hard fields with tighten mode, intersect (for list-shaped fields like tool_allowlist) or take the more restrictive value (for numeric fields like top_k where methodology override may only decrease).
  - invoke_agent use case shape. Takes (tenant_context, agent_template_id, user_input). Resolves agent template, role template (via RoleLookup per S26a-2), methodology template if bound (via MethodologyLookup per S26a-2). Composes effective constraint bundle per D87 resolver. Builds AgentInvocationContext (role base, methodology overlay, retrieved chunks pre-fetched if retrieval_strategy demands proactive retrieval, user input). Invokes executor. Captures cost via OTel spans per D49. Emits audit events at start and end per D26. Returns AgentResult.
  - Cost capture extension. Per-agent-invocation cost aggregates from per-LiteLLM-call OTel spans tagged with `gen_ai.cost.input_usd`, `gen_ai.cost.output_usd`, `gen_ai.cost.total_usd`. The TraceQueryPort from D56 extends with a per-invocation aggregation query or an additional method per the cleanest extension shape resolved at pre-write reconciliation.
  - Audit shape. Two audit rows per invocation (start, end) on the per-tenant audit chain per D26. End row payload: response_hash + cost_total_usd + iteration_count + termination_reason (one of: content, max_iterations, error). Hashes computed via `padhanam.security.hash_chain.compute_revision_hash`.

(b) Provider-specific agent SDK (Anthropic agent loop, OpenAI Agents SDK): rejected per the orchestration architecture deferred-decisions entry framing on provider coupling as configuration. (c) No tool loop at Phase 1, pure LLM-with-pre-fetched-context: rejected because the LLM-with-tool-loop control flow is the substantive complexity; building two different runtime shapes (no-loop at S27b, loop at S28b) is more cost than landing the loop once with retrieval-as-only-callable. ### Commit 3. D87 override-mode resolver

`feat(p8/s27b): add D87 override-mode resolver at contexts/agent/application/composition.py`

- New module `contexts/agent/application/composition.py` with `compose_effective_constraint_bundle(role: RoleView, methodology: MethodologyView | None, role_id_in_methodology: UUID | None) -> EffectiveConstraintBundle`.
- The composition algorithm per D87 mode space:
  - augment (soft): role base + "\n\n" + methodology override value
  - replace (soft): methodology override value substitutes
  - tighten (hard, list-shaped): intersection of role base list and methodology override list
  - tighten (hard, numeric): take the more restrictive value (lower for top_k caps, higher for min_score floors, lower for cost_ceiling caps)
- If methodology is None, the effective bundle equals the role's base bundle (no overlay applied).
- Validation: per D87, inadmissible (field, mode) pairs raise at methodology write time; composition trusts the validation and proceeds without re-checking.
- Unit tests: augment mode for system_prompt produces concatenated string with the separator; replace mode substitutes; tighten mode for list and numeric fields; no-methodology case returns role base; LVT case (one role_ref with empty overrides) returns role base unchanged; McKinsey ProblemFramer case returns augmented system_prompt.

### Commit 4. AgentLoopExecutor adapter

`feat(p8/s27b): add AgentLoopExecutor adapter implementing AgentExecutor against LiteLLM`

- New module `contexts/agent/adapters/outbound/agent_loop_executor.py`.
- Constructor takes the LiteLLM adapter (located per pre-write reconciliation), the RetrievalClient, the cost-capture path, the audit emission path.
- Implements `execute()`:
  1. Emit start audit event.
  2. If retrieval_strategy is "proactive", retrieve chunks before the first LiteLLM call and prepend to user input as context.
  3. Build initial message list: system message (effective_system_prompt), user message (user_input plus pre-fetched chunks if proactive retrieval).
  4. Loop, max 10 iterations:
     - Call LiteLLM. Capture cost.
     - If response has content only, terminate with `termination_reason=content`.
     - If response has tool_calls naming "retrieval": invoke RetrievalClient per effective_retrieval_constraints; format chunks as tool result message; append to message list; continue.
     - If response has tool_calls naming anything else: terminate with structured error response indicating tool not registered.
     - On iteration N=10 without content termination: terminate with `termination_reason=max_iterations`.
  5. Emit end audit event with response_hash and cost_total_usd.
  6. Return AgentResult.
- Unit tests covering: content-only response (terminates iteration 1); single tool-call to retrieval then content (terminates iteration 2); two tool-calls then content (terminates iteration 3); tool-call to unknown tool (terminates with error response); max-iterations cap.
