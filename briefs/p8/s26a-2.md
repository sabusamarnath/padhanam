### Commit 1: `feat(p8/s26a-2): add source_role_id lineage to agent_templates`

Alembic revision against the per-tenant track:

1. Adds `source_role_id uuid` and `source_role_version integer` to `agent_templates`.
2. Adds CHECK constraint `agent_templates_role_lineage_paired_null`.
3. Backfill: for each existing `agent_template` with non-null `source_methodology_template_id` and `source_methodology_template_version`, fetch the methodology revision via the control-plane connection, read the first entry in its `role_refs`, populate `source_role_id` and `source_role_version` from that entry. For PM agent at tenant a, this resolves to LVTGuide UUID and version 1 per S26a-1's 0007_lvt_split. For blank-created agents (lineage NULL), the new columns stay NULL.
4. Down-migration: drops the CHECK constraint and both columns.

Verify with `make migrate` against the existing tenant a database; confirm PM agent's row has both lineage pairs populated.

### Commit 2: `feat(p8/s26a-2): agent domain gains role lineage fields`

Changes:

- `AgentTemplate` frozen dataclass: add `source_role_id: UUID | None` and `source_role_version: int | None`.
- Domain invariant: paired-null applies to both lineage pairs independently. Tests cover the four valid combinations and the four invalid ones.
- `create_agent_from_methodology` use case: update to populate role lineage by reading `MethodologyView.role_id` and `MethodologyView.role_version` (the view from S26a-1's adapter already joins methodology + role; the use case reads the role pair directly without an additional cross-context call).
- AgentRepositoryPort and the Postgres adapter: extend to persist and read the new columns.

Tests: domain invariant tests; use case test confirming methodology-based clones produce both lineage pairs populated.

### Commit 3: `feat(p8/s26a-2): RoleLookup cross-context port and create_agent_from_role use case`

Changes:

- `contexts/agent/application/ports/role_lookup.py`: `RoleLookup` callable Protocol with method `lookup(role_id: UUID, role_version: int | None) -> RoleView`. `RoleView` frozen dataclass with the role's content fields (system_prompt, source_ids, tool_allowlist, retrieval_strategy, filter_tree, top_k, min_score, model_selection) plus metadata (role_id, resolved role_version, role_name, role_description).
- New use case `create_agent_from_role` at `contexts/agent/application/use_cases.py`: accepts role_id, optional role_version, name, source_ids. Resolves role via `RoleLookup`. Constructs `AgentTemplate` with `source_role_id` and resolved `source_role_version` populated; methodology lineage stays NULL. Constructs `AgentRevision` version 1 with content fields copied from `RoleView` and source_ids from the request after `SourceLookup` validation per D79. Persists.
- Adapter in `apps/cli/_cross_context.py`: `RoleLookupAdapter` wrapping the role context's `get_role_template` use case. Same shape as `MethodologyLookupAdapter`.

Tests: use case unit tests; agent independence post-clone (D68); cross-context import-linter still passes; no domain or application layer imports from `contexts.methodology` in agent.

### Commit 4: `feat(p8/s26a-2): CLI commands for padhanam role and padhanam agent create-from-role`

Five commands at `padhanam role`:

- `padhanam role create --config <path>` (operator-context only; config carries name, description, system_prompt, source_ids, tool_allowlist, retrieval_strategy, filter_tree, top_k, min_score, model_selection)
- `padhanam role get <role-id> [--version N] [--json]`
- `padhanam role list [--include-archived] [--json]`
- `padhanam role update <role-id> --config <path>`
- `padhanam role archive <role-id>`

New agent command:

- `padhanam agent create-from-role --tenant <label> --config <path>` (config carries `role_id`, optional `role_version`, name, source_ids)

Auth posture: role commands inherit methodology's any-authenticated-read, operator-context-for-writes; agent create-from-role inherits agent CRUD's tenant-context-or-operator-context per D75.

Tests: CLI command unit tests; end-to-end command-line invocation tests against a test database.

### Commit 5: `chore(p8/s26a-2): import-linter, tenant isolation tests, restore docker e2e`
