## Substantive work (commits 2 onward)

### Commit 2: Domain entities

```
feat(p13/s43): Case, DataPoint, Assertion domain entities
```

Add `contexts/state_persistence/domain/case.py`, `data_point.py`, `assertion.py`. Frozen dataclasses or Pydantic models per the existing convention (verified at pre-write reconciliation). Each entity carries:

- `Case`: id (UUID), tenant_id (UUID), title (str), case_type (str enum: PORTFOLIO_ITEM at Phase 2-A; substrate accepts other types), created_at, updated_at, status (str enum: OPEN, CLOSED, ARCHIVED).
- `DataPoint`: id (UUID), case_id (UUID), tenant_id (UUID), data_point_type (str enum: GOAL, STATUS, METHODOLOGY_APPLICATION at Phase 2-A; substrate accepts other types), value (JSON), authored_by (ActorReference; placeholder until S44 commits ActorContext), created_at, certainty (float between 0 and 1; default None pending tiered-by-salience implementation at P15).
- `Assertion`: id (UUID), data_point_id (UUID), tenant_id (UUID), assertion_type (str enum: INITIAL, REVISION), revises_assertion_id (UUID nullable; FK back to a prior Assertion if REVISION), value (JSON), authored_by (ActorReference), created_at.

Unit tests cover construction, validation, type-enum handling.

### Commit 3: Revisable Protocol

```
feat(p13/s43): Revisable Protocol shape per D125
```

Add `padhanam/protocols/revisable.py` (path verifies at pre-write reconciliation). Define:

```python
class Revisable(Protocol):
    def revise(self, change: AssertionChange, actor: ActorReference) -> "Revisable":
        ...

    def revision_history(self) -> list[Assertion]:
        ...
```

The protocol contract: revisions append a new Assertion to the entity's revision history; the latest Assertion is the current state; prior Assertions are queryable. Implementations live at the entity level (DataPoint implements Revisable; Case may or may not implement Revisable per session-close decision).

Unit tests cover the protocol contract: revising appends, history queries return ordered list, the latest assertion is the current state.

### Commit 4: Alembic migration

```
feat(p13/s43): Alembic migration for state persistence tables
```

Per-tenant Alembic migration creating tables: `cases`, `data_points`, `assertions`. Schema reflects domain entities. Foreign keys with cascade-delete from Case to DataPoint to Assertion. Indices on tenant_id, case_id (for DataPoint), data_point_id (for Assertion), created_at (for ordering).

Migration runs successfully against a fresh per-tenant database. Down-migration restores prior state.

### Commit 5: Repository adapter

```
feat(p13/s43): Postgres repository adapter for state persistence
```

Add `contexts/state_persistence/adapters/postgres_state_persistence.py`. Implement repository interface (defined at the same context's `adapters/repository.py` or equivalent path per convention). Methods:

- `save_case(case: Case) -> Case`
- `get_case(case_id: UUID, tenant_id: UUID) -> Case | None`
- `list_cases(tenant_id: UUID, case_type: str | None, status: str | None, cursor: str | None) -> CaseListResult` (cursor pagination per S33 codec convention).
- `save_data_point(data_point: DataPoint) -> DataPoint`
- `get_data_point(data_point_id: UUID, tenant_id: UUID) -> DataPoint | None`
- `list_data_points(case_id: UUID, tenant_id: UUID, data_point_type: str | None) -> list[DataPoint]`
- `save_assertion(assertion: Assertion) -> Assertion`
- `assertion_history(data_point_id: UUID, tenant_id: UUID) -> list[Assertion]` (ordered chronologically).

Tenant-isolation enforced at adapter level: every method requires tenant_id; cross-tenant queries return empty or None and emit a tenant-scope-violation security event per the existing convention.

Unit and contract tests cover round-trips, isolation, ordering, cursor pagination.
