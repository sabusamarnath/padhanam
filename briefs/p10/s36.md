## Appendix D — Pre-write reconciliation outcomes (2026-05-14)

Reconciliation fired its fifteenth instance at S36 session-open
(first P10 instance). Three reconciliation passes per the
brief's three-surface framing plus four brief-shape corrections
captured at write time.

**Finding 1 — Audit context port-location asymmetry (operator
question).** The brief at "Commit 3: read port" specifies a new
`contexts/audit/ports/reader.py` mirroring `contexts/run_history/
ports/`. The existing write-side `AuditPort` sits at
`contexts/audit/domain/ports.py` (pre-P9 convention). Three
options framed at the operator user-question: (A) brief's call —
new `ports/reader.py` only, write-side port unchanged
(asymmetry within audit, symmetry with run_history at the read
port); (B) move existing `AuditPort` to `contexts/audit/ports/
writer.py` simultaneously, full structural symmetry; (C)
co-locate both ports in `contexts/audit/domain/ports.py`,
consistent within audit but asymmetric with run_history.
Operator selected option (A) on minimal-touch grounds. The
intra-context asymmetry is recorded as a carryover at
`charter/current-package.md` with activation trigger named (next
port added to the audit context).

**Finding 2 — Chain helper reuse is partial, not wholesale.**
The brief at "Commit 4: Postgres adapter" reads "Chain
verification reuses existing helpers at `contexts/audit/domain/
events.py`." The existing `verify_chain(events)` walker at
`contexts/audit/domain/events.py:95` walks from `GENESIS_HASH`
and reports `break_index=0` for any input whose first row's
`previous_event_hash` differs. For a page-granularity verifier
that may start mid-chain, this is structurally inapplicable.
The reusable primitives are `compute_event_hash` (the per-row
recomputation) and `GENESIS_HASH` (the sentinel for head-of-
chain detection); the walker itself is new logic on top. The
correction lands at write time in D102 alternative (h) and in
the commit 4 adapter docstring; no brief shape change.

**Finding 3 — Read-side `AuditEventRecord` is a new value object
distinct from `AuditEvent`.** The existing domain `AuditEvent`
dataclass at `contexts/audit/domain/events.py:21` omits `id`
(Postgres generates server-side via `gen_random_uuid()` and the
write-path adapter never reads it back). The brief's read DTO
`AuditEventRecord` carries `id` per the 13-column table shape.
Two coexisting value objects: write-side `AuditEvent` without
`id`, read-side `AuditEventRecord` with `id`. Same pattern as
`AgentRunRecord` versus `RunRecord` at run_history. No brief
change.

**Finding 4 — Schema column count is 13, not 12.** Brief
language at the P10 epic forecast and at "Pre-write
reconciliation" surface 2 names "12 columns." Actual schema at
`charter/schema.md:54-68` (control plane) and `:326-340` (per-
tenant) carries 13 columns including the `id` UUID primary key.
Brief-shape miscount; corrected at write time in the P10 epic
and D102.

**Finding 5 — D-entry numbering clean at D102.** Verified at
`charter/decisions.md` tail; D101 is the latest entry. No
collision.

**Finding 6 — Principal-derived tenant context 404 behaviour
confirmed.** `get_tenant_context` at `apps/api/routers/
inference.py:81-124` returns 404 for tenant-not-in-registry,
400 for non-UUID `tenant_id`, 503 for "registry not configured."
Brief assumption holds.

**Finding 7 — Tuple-comparison defence-in-depth pattern exists
live.** S33's `sa.cast(..., pg.UUID)` pattern is in the run-
history Postgres reader; the audit reader will mirror.

Find-rate distribution at S36 session-open: one operator-

**Finding 8 — Pydantic v2 versus frozen dataclass for domain
value objects.** The brief at commit 2 specifies
"immutable Pydantic v2 model" for `AuditEventRecord`. The
existing write-side `AuditEvent` at `contexts/audit/domain/
events.py:21` is a frozen dataclass, and the run_history
sibling at `contexts/run_history/domain/run_record.py:34`
also uses frozen dataclass. The codebase pattern at the
domain-value-object layer is frozen dataclass; the brief's
"Pydantic v2 model" wording is brief-shape carryover from
HTTP-layer convention. Resolved at write time: all four new
domain modules use frozen dataclasses with `__post_init__`
validation, matching siblings. No operator decision needed —
this is alignment with the established codebase convention.

**Finding 9 — Time-window filter shape: one timestamp_range,
not two.** The brief at commit 2 lists filter dimensions as
"the seven framing candidates (`started_at_range`,
`ended_at_range`, ...)" — eight names labelled as seven, with
both `started_at_range` and `ended_at_range`. The audit
schema has a single `tenant_audit.timestamp` column (point-in-
time events, no duration); the brief's two-bound shape is
copy-paste from run_history where `runs.started_at` and
`runs.completed_at` are distinct columns. Resolved at write
time: `AuditEventListFilters` carries one `timestamp_range`
field (lower-inclusive, upper-exclusive tuple) per the
schema's single-timestamp shape. Seven filter dimensions in
total: `timestamp_range`, `actor`, `action_verbs`,
`resource_type`, `resource_id`, `correlation_id`,
`jurisdiction`. No operator decision needed — schema-shape
correction.
