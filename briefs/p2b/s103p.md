# Session prompt — The "how am I doing" assessment: the verdict that reads the real shape

**Mode:** build session, view-layer (one read-only projection + its render). The payoff surface the whole opportunity layer was built to feed.
**Line:** Phase 2-B, the get-a-job framework build. The assessment reads the now-real opportunity set (S103o) and the closed state (S103n) and tells the operator how the search is actually going.
**One-line aim:** render a recommendation-shaped assessment of get-a-job — an empty-pipeline verdict anchored on the label-independent funnel, the move it implies, and the close-reason split shown as the *proof-dependent sharpener* — reading live, so it shows the honest unproofed state and motivates the proof pass rather than waiting on it.

This is **option 2** (build now, reading live): the verdict is conditional where it must be, and the surface is what nudges the operator to proof the 14 suggested opportunities. The win-probability engine (slice three) is out; this first cut reads counts and the closed-reason split only.

---

## The load-bearing design rule (the one thing this session must get right)

**The headline verdict must rest only on label-independent evidence; the close-reason split must only *sharpen* it, never *flip* it.**

The v2 mock asserted "response failure, not conversion failure" as settled — but that diagnosis depends on the close reasons, which are unproofed, and the *suggested* reasons (9 rejected) actually argue the opposite (conversion failure). A verdict that flips on an input the operator hasn't confirmed is the one move the assessment may never make.

The fix, which is also the stronger reading:
- **The dominant signal is the silence rate, which needs no close-reason proof.** Of the tracked applications, only the multi-touch ones (the 17 opportunities) drew any reply at all; the long one-touch tail drew silence; ~1 reached interview; 0 offers. "You are not being read" is fully supported by that funnel collapse, independent of why the few that engaged closed.
- **The close-reason split is a second-order refinement *within* the engaged set** — "of the few who replied, did they evaluate-and-pass (conversion) or go cold (response)?" — and it is **proof-dependent**: present it as "confirm the reasons and I can sharpen this," not as the thing the headline rests on.

So the verdict **sharpens** on proof; it does not flip. Build it that way.

## What the build does

A read-only assessment for get-a-job, recommendation-shaped (D9), reachable from the assess surface (a new mode/panel; reuse the existing toggle chrome). It renders:

1. **The verdict** — anchored on the label-independent funnel: pipeline empty (0 confirmed live), the constraint is upstream of interviews (the applied→engaged collapse), with a "because" that cites only certain numbers, and a **move** that follows the framework's response-rate levers (sharper targeting, warm introductions) — originate again, differently; not interview prep for a problem upstream of interviews.
2. **The proof-dependent split** — the close-reason interpretation as two reads (as-suggested → conversion problem; as-likely-corrected → response problem), explicitly flagged "this sharpening depends on reasons you haven't proofed," linking the operator to the lens to proof. It refines the move's *emphasis*, not the headline.
3. **The funnel** — applied / any reply / interviewed / offer, every number traced to a live read, the leak stage marked.
4. **The opportunity gauge** — "0 / 17 confirmed live," 11 closed · 6 system-suggested awaiting proof, the closed set named as the first win-probability calibration body (proofed reasons → real calibration).

The verdict + funnel logic is a **pure domain function** (the goal_assessment verdict precedent — deterministic, traceable, never an LLM); the render is a projection. No writes — the proof actions already live in the lens (S103n/S103o).
