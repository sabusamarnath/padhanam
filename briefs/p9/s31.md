- **Audit emission lives in the executor, not in `invoke_agent`.**
  Per `invoke_agent` docstring at
  `contexts/agent/application/use_cases.py:716-722`: "Audit
  emission per D26 happens inside the executor … The two audit

  yields)." Auth-failed invocations never reach
  `executor.execute`, so they produce no audit row and no event
  yields. The reflection prompt 3 four-state matrix resolves
  with: auth-failed = no audit row, no event yields, no runs row.
  No fifth state needed for that case.

- **`InvocationFailed.partial_audit_chain_state` is variable-
  length: 0, 1, or 2 hashes.** Three emission sites at
  `agent_loop_executor.py:152-164` (pre-start-audit failure →
  empty), `agent_loop_executor.py:434-441` (loop-body unhandled
  exception → 1 hash), `agent_loop_executor.py:449-465` (end-
  audit emission failure → 1 hash). The 2-hash variant is
  documented as forward-affordance in `events.py:200-214` but no
  executor codepath currently produces it. Brief's
  `audit_end_hash NOT NULL CHECK length 64` commitment fails
  for the 0-hash and 1-hash cases. Resolved by user question at
  commit 1: schema relaxes `audit_end_hash` to nullable under
  `termination_reason='failed'` only, with CHECK
  `(termination_reason = 'failed') OR (audit_end_hash IS NOT
  NULL)`. Write-time mapping at commit 6: 0-hash → skip writer
  call (Q1 Option 1 framing extends naturally); 1-hash → write
  with `audit_end_hash=NULL`, `termination_reason='failed'`;
  2-hash (forward-affordance) → write with both hashes,
  `termination_reason='failed'`. State matrix gains a fifth
  client-visible state (post-start-audit failure with 1-hash
  InvocationFailed event, runs row with NULL end-hash).

  invariant_blocked, failed}`. Actual enum at
