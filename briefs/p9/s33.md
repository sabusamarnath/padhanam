The cursor is opaque to consumers; the adapter serialises as base64 of a stable JSON shape so cursor strings survive serialisation across HTTP boundaries at S34. ### Structural-honesty finding (operator-resolved at session-open)

**Finding S1 — `RunWithCitations` wrapper structurally redundant with existing `RunRecord`.** The brief's drafted Goal section commits a new `RunWithCitations` aggregate DTO carrying `run: RunRecord`, `chunk_citations: tuple[ChunkCitationRecord, ...]`, `entity_citations: tuple[EntityCitationRecord, ...]`. But `RunRecord` (as extended at S32 per D96) already carries `chunk_citations: tuple[ChunkCitationRecord, ...]` and `entity_citations: tuple[EntityCitationRecord, ...]` as direct fields with default empty tuples. The drafted `RunWithCitations` would have been a thin wrapper duplicating fields already present on `RunRecord`. The brief's own Appendix A D97 Choice text states "the read DTO is symmetric with the write side: the same record types travel both directions" — which points to reusing `RunRecord` directly. The wrapper would have contradicted the symmetry claim by introducing a wrapper that does not exist on the write side. Operator resolution at session-open via AskUserQuestion: drop the wrapper; `get_run` returns `RunRecord | None`. D97 as landed names `RunRecord`-as-aggregate explicitly and records the wrapper-vs-record choice in alternative (k).

**Sub-finding S1b — Citation sort key.** The brief's commit-3 description says citation tuples at `get_run` time are "sorted by `created_at` for stable rendering." But `ChunkCitationRecord` and `EntityCitationRecord` do not carry a `created_at` field (the column exists on the per-tenant tables but was not lifted onto the domain records at S32 because the records were write-shaped). Two options surfaced: (a) sort by `id ASC` (deterministic, no domain change); (b) add `created_at` to both domain records (one-field extension, chronological order). Operator resolution at session-open: sort by `id ASC`. D97 alternative (l) records the sort-key reasoning.
