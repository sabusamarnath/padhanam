- Tenant isolation extends to the new column via the existing `tests/contract/tenant_isolation/` harness per D24.
- D62 records the choice and the build-time refinements.

**`charter/decisions.md`** — append D62. Indicative text:

```
- **D62: Embedding model default and chunk-embedding column shape — nomic-embed-text via Ollama, single column on chunks, HNSW cosine** (Package P6, Session S20, 2026-05-XX)
  - Choice: The default embedding model is `nomic-embed-text` served via
    Ollama, accessed through LiteLLM's OpenAI embeddings API path so the
    gateway routing reuses the inference adapter's HTTP infrastructure.
    The chunk's embedding lives as a single `embedding vector(768)`
    column on the existing `chunks` table per per-tenant Alembic
    revision 0006; an HNSW index using cosine distance lands in the
    same migration. `default_embedding_model` joins `InferenceSettings`
    in `padhanam/config/inference.py`, parallel to the existing
    `default_model` for generative inference. The pricing table at
    `padhanam/config/inference.py` extends with the embedding model
    entry. Embedding cost flows through the existing trace-attribution
    path per D41 with no new architectural surface. The SourceState
    enum extends with `embedding`, `embedded`, `embedding_failed`; the
    worker polls for `parsed`, claims the source, embeds chunks via
    UPSERT on chunk_id for idempotent re-embed, and transitions state
    through `embedding` to `embedded`.
  - Reasoning: nomic-embed-text has the longest track record of the
    credible Ollama-served embedding models, 768-dim is a reasonable
    storage cost in pgvector at Phase 1 corpus sizes, the OpenAI-API
    shape means LiteLLM routing reuses the inference path the chat
    adapter already uses, and the smaller parameter count keeps
    inference cost tractable on the constrained dev hardware (S6
    reflection: ~19 tok/s on Qwen 2.5 7B as the local-laptop ceiling).
    Single-column shape on chunks keeps worker logic and the pgvector
    index simple; flexibility for multi-model A/B testing has no
    consumer at Phase 1 and the migration to a separate
    chunk_embeddings table is cheap if a real consumer arrives. HNSW
    plus cosine matches pgvector's default for higher-dimensional
    retrieval workloads and the model's recommended distance metric.
  - Alternatives considered: mxbai-embed-large (rejected: marginally
    better benchmarks at meaningfully higher inference cost on
    constrained dev hardware; revisit if eval harness surfaces
    retrieval-quality problems); separate chunk_embeddings table with
    FK (rejected: paper architecture at Phase 1, multi-model A/B
    testing has no consumer, separate-table migration is cheap if
    needed later); IVFFlat index (rejected: HNSW is pgvector default
    for higher-dim retrieval with better query performance at higher
    accuracy; IVFFlat requires periodic re-clustering); L2 or inner-
    product distance (rejected: nomic-embed-text recommends cosine);
    embedding via direct Ollama call bypassing LiteLLM (rejected:
    breaks D27's portability boundary; LiteLLM is the gateway).
  - Kano: must-have on both halves. Embedding model default gates
    every later retrieval evaluation; chunk-embedding column shape
    gates the schema and pgvector index strategy.
```

**`charter/schema.md`** — extend the chunks table section with the new column and the index, and update the SourceState enum reference to include the new states. Indicative additions to the chunks table:

### Commit 1: `docs(charter): land S20 framing decisions`

### Commit 2: `feat(p6/s20): chunks embedding column and HNSW index`
- Per-tenant Alembic migration `0006_add_chunk_embedding`:
  - `embedding vector(768)` column on chunks (nullable).
  - HNSW index `chunks_embedding_hnsw_idx` using `vector_cosine_ops`.
- Verify pgvector extension is enabled (S5 enabled it for the per-tenant DBs in the initial schema; confirm via the migration's idempotent guard).
- Tenant-isolation tests extended to verify the new column is tenant-scoped.

### Commit 3: `feat(p6/s20): ChunkEmbedder port and LiteLLM adapter`
- `contexts/ingestion/ports/chunk_embedder.py`: `ChunkEmbedder` Protocol with `embed(chunks: Sequence[Chunk]) -> Sequence[Embedding]` shape (per-batch shape; the per-chunk shape settles in build if batch-level surfacing is awkward against LiteLLM's API).
- `contexts/ingestion/adapters/outbound/embedding/litellm_embedder.py`: implementation calling LiteLLM's `/v1/embeddings` endpoint, reusing the HTTP client infrastructure the existing inference adapter establishes.
- `padhanam/config/inference.py`: `default_embedding_model` setting added to `InferenceSettings`; pricing table extends with the embedding model entry per D41.
- Unit tests against `httpx.MockTransport` covering: successful single-chunk embed, batch embed, error response handling, model-mismatch error handling.

### Commit 4: `feat(p6/s20): embedding worker stage`
- Extend `SourceState` enum: `embedding`, `embedded`, `embedding_failed`. Migration extends the CHECK constraint on the chunks state column accordingly (verify whether the state column is on `sources` or `chunks` per the S19 build).
- `application/embed_source.py`: claims a parsed source via `claim_pending_for_embed` (mirroring `claim_pending_for_parse` from S19), invokes `ChunkEmbedder` against the source's chunks, persists embeddings via UPSERT on `chunk_id`, transitions source state to `embedded`. UPSERT semantics ensure idempotency on retry.
- `apps/cli/_ingest.py`: worker loop extends to poll for `parsed` state alongside `received` (the worker is now pipeline-staged, not single-stage).
- Integration test against tenant a's data plane: register a markdown source, run the worker through parse and embed, verify chunks have non-null embeddings and source state transitioned to `embedded`.
- Reentrancy and idempotency tests parallel to S19's: stop the worker mid-embed and restart; run the worker against an already-embedded source.

### Commit 5: `feat(p6/s20): embedding cost-capture verification`
- End-to-end test: invoke `padhanam ingest run` against a markdown source, run worker through parse and embed, verify the OTel trace for the embedding request lands in Langfuse with `tenant.id` and `tenant.jurisdiction` span attributes plus `gen_ai.usage.input_tokens` populated.
- If `gen_ai.usage.input_tokens` is missing for embedding requests against Ollama-served `nomic-embed-text` through LiteLLM, document the gap in the session log reflection and either bridge in the LiteLLM adapter or land as forward-affordance for the next cost-attribution session. Do not let cost-attribution silently fail.

## Acceptance criteria

1. `make migrate` applies revision `0006_add_chunk_embedding` to both tenant databases idempotently.
2. `make lint` returns the expected import-linter contract count (existing 17 plus net additions if any from the new ports module); 0 broken.
3. `uv run pytest` returns greater than the S19 baseline (294 passed, 7 skipped) by the count of new tests added; existing tests untouched and passing.
4. End-to-end: `padhanam ingest run sample.md` against tenant a, then `padhanam ingest worker` (or `make ingest-worker`); the source transitions through `parsed` to `embedded`; chunks table rows have non-null `embedding` columns with 768-dimension vectors.
5. Tenant-isolation contract tests pass for the new column on both reads and writes.
6. pgvector HNSW index exists on `chunks(embedding)` for both tenant databases; an `EXPLAIN` against a vector-distance query confirms index usage.
7. OTel traces from embedding requests appear in Langfuse with `tenant.id` and `tenant.jurisdiction` span attributes; cost-per-successful-task computation works against embedded sources, or the attribution gap is documented in reflection.
8. Worker reentrancy: stopping the worker mid-embed and restarting completes the source from the appropriate recovery state with no duplicate embeddings.
9. Worker idempotency: running the worker against an already-embedded source is a no-op.
10. Concurrency: the SKIP LOCKED concurrency test from S19 extends to cover the embedding stage; no double-embedding under concurrent worker simulation.
