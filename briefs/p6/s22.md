## Goal

- A `RetrievalClient` port lives at `contexts/ingestion/ports/retrieval_client.py` with two methods: `search_vector(query: str, scope: TenantContext, limit: int) -> Sequence[ChunkResult]` and `traverse_graph(seed: str, scope: TenantContext, depth: int) -> Sequence[EntityResult]`. Hybrid composition is an agent-layer concern per D5 and does not land at P6.
- A pgvector-based vector adapter at `contexts/ingestion/adapters/outbound/retrieval/pgvector_search.py` performs cosine-distance search against the chunks table with the per-source state filter (only chunks from sources where `state = 'indexed'` surface).
- A Neo4j-based graph adapter at `contexts/ingestion/adapters/outbound/retrieval/neo4j_traverse.py` performs graph traversal through the existing `TenantScopedNeo4jSession` wrapper from S21, with the per-source state filter implemented as a Cypher predicate against the chunk-source join.
- The `ChunkEmbedder` port refines to take an explicit `task: EmbeddingTask` parameter (enum: `DOCUMENT`, `QUERY`); the LiteLLM adapter applies the model-specific prefix (`search_document:` versus `search_query:`) based on the task hint. The retrieval-side query embedding uses `EmbeddingTask.QUERY`.
- The vector adapter calls the embedder with `EmbeddingTask.QUERY` to embed the query before cosine search; embedding cost flows through the existing trace-attribution path per D41.
- D65 records the RetrievalClient port surface, the cross-track readiness semantics, and the ChunkEmbedder task-hint refinement, with build-time refinements absorbed per the framing-prompt-as-recommendation pattern.
- Tenant isolation contract tests extend to cover both retrieval methods on both tenants.
- An end-to-end test ingests a markdown source through to `indexed`, then exercises both retrieval methods and asserts non-empty, tenant-scoped results.
